# RepoDeck

[English README](README.en.md)

RepoDeck は、複数リポジトリ(複数プロジェクト)のウィンドウ配置を「ワークセット」として
まとめて管理し、グローバルホットキーとクイックスイッチャーで瞬時に切り替えられる
Windows デスクトップアプリです。Claude Code / Codex のライフサイクルフックと連携し、
各ワークセットの AI エージェント実行状況(実行中・入力待ち・完了)をバッジとトレイ
アイコンの色で表示します。

できること(概要):

- **セット切替** — ホットキー1つで、そのプロジェクトのウィンドウ一式をメイン画面へ
  復元。使っていないセットは別画面へ退避、または最小化
- **閉じていても復元** — 閉じたアプリは登録した引数(VS Code のフォルダー、ブラウザの
  URL など)で起動し直してから配置
- **エージェント状態** — Claude Code / Codex の実行中・入力待ち・完了をセットごとに表示
- **git / GitHub 状態** — ブランチ、変更数、未push、PR、CI 結果を一覧に表示

- Rust + [Slint](https://slint.rs) 製、Windows ネイティブ (C#/WPF 非依存)
- 完全ローカル動作。ネットワーク通信・テレメトリーなし
- インストーラー不要。`repodeck.exe` を実行するだけ

## インストール

1. [Releases](https://github.com/zappyzed100/repodeck/releases) から
   `RepoDeck-v<version>-windows-x64.zip` をダウンロード
2. 好きなフォルダーへ展開(管理者権限・インストーラー不要)
3. `repodeck.exe` を実行 — タスクトレイにアイコンが常駐します

## 30秒で試す

1. `repodeck.exe` を起動(タスクトレイにアイコンが表示される)
2. トレイアイコンを右クリック →「新しいセットを登録」で、現在開いているフォルダー/
   ウィンドウをワークセットとして登録
3. 別のフォルダーでも同様にもう1つワークセットを登録
4. `Ctrl+Alt+W` (既定のホットキー) を押すとクイックスイッチャーが開く
5. 登録した2つのセットが一覧表示されるので、クリックまたは ↑/↓ + Enter で
   切り替え — 選択中でないセットのウィンドウは自動的に退避(退避先へ移動、または最小化)

## 使い方

### ワークセットの登録

タスクトレイメニューの「新しいセットを登録」、またはクイックスイッチャーの
「セット管理を開く」からセット管理画面を開き、フォルダーを選択します。フォルダーの
親方向に `.git` が見つかればそのルートを、なければ選択したフォルダー自体を
リポジトリとして登録します。現在画面に表示されているウィンドウのうち、登録したい
ものにチェックを入れて保存すると、その配置(位置・サイズ・最大化状態)が記録されます。

### クイックスイッチャー

- 既定のホットキー: `Ctrl+Alt+W` (設定画面から変更可能)
- ホットキーまたはトレイアイコンの左クリックで表示/非表示をトグル
- 検索ボックスに入力してセット名・リポジトリパスで絞り込み
- ↑/↓ + Enter、マウスクリックで切替
- 各行の右端に操作列: **×**(そのセットのアプリを閉じる)、**▲▼**(並び順を変更)。
  並び替えは手動順を書き換えて即保存します(絞り込み中は並びが全体と一致しないため
  ▲▼ は非表示)
- **押しっぱなし切替 (Alt+Tab風)**: ホットキーの修飾キーを押したまま `↑`/`↓` を
  タップするとクイックスイッチャーが開き、上下でセットを選べます。修飾キーを
  離した瞬間に、選択中のセットへ切り替わって閉じます (既定では `Ctrl+Alt` を
  押しながら `↑`/`↓`)
- Esc または右上の ✕ で閉じる。設定でフォーカスを失ったときに自動的に閉じるようにもできる

### 起動候補(アプリ登録)からセットを作る

ウィンドウをキャプチャする方式に加えて、**アプリを先に登録しておき、それを並べて
セットを宣言する**方式が使えます。アプリが起動していなくても(インストール直後でも)
セットを作れるのが利点です。

1. セット管理の「起動候補を登録」で、アプリを登録します。スタートメニューから選ぶ、
   実行ファイルを参照する、名前とパスを直接入力する、のいずれでも可
2. セット登録画面で登録済みアプリを選び、**どの画面のどこに開くか**を指定して「追加」
3. アプリごとに必要な入力だけが表示されます — VS Code はフォルダー/ワークスペース、
   ブラウザは URL、それ以外は起動引数

配置は**プレビューを見ながら選べます**。メイン画面が実際の並び・比率のまま描画され、
分割(1/2/4)のセルを直接クリックして位置を決められます。画面名だけでは分からない
「どっちが左か」「どのセルか」が一目で分かります。

### 閉じたアプリを開き直す / ウィンドウを閉じる

セット管理でセットを選ぶと、各ウィンドウの現在の状態(バインド済み/未検出)が出ます。

- **閉じたアプリを開き直す** — 閉じているアプリを、登録した引数で起動し直して配置します。
  起動が遅いアプリ(WinForms や Tauri 製など)も、ウィンドウが現れるまで待って
  紐づけます。リモートデスクトップのように接続ダイアログが本体に差し替わるアプリも
  追従します
- **ウィンドウを閉じる** — そのセットのアプリを終了します(セット自体は残るので、
  次に切り替えれば起動し直されます)。既定は `WM_CLOSE` なので、保存確認などは
  アプリ側に委ねられます

### 退避せず最小化(ウィンドウ単位)

別のセットへ切り替えたとき、ウィンドウは既定では退避先へ**移動**します。ブラウザなど
「動かすより最小化してほしい」ウィンドウは、セット管理の詳細でウィンドウごとに
**「退避せず最小化」**にチェックを入れてください。切替時と「メイン画面を空にする」の
両方で、移動ではなく最小化されます。

### メイン画面を空にする

メイン画面のウィンドウを一括で片付けます。登録済みウィンドウは退避先へ、未登録の
ウィンドウは確認ダイアログでチェックしたものを最小化します。直後なら「元に戻す」で
復元できます。クイックスイッチャーの一番下からも実行できます。

### レイアウトスタジオ(画面構成と退避先)

トレイメニューの「レイアウトスタジオ」から、モニター構成を設定します。

- **メイン画面**: セットを表示する画面。複数指定でき、画面ごとに自動分割(1/2/4)を指定
- **操作対象にしない**: RepoDeck に触らせない画面を除外
- **サブ画面(退避先エリア)**: 退避専用の領域を名前付きで定義し、セットごとに
  「このセットはここへ退避」と指定できます。1つのサブ画面を複数セットで共有した
  場合は 1→2→4 と分割して割り当てます

### 設定画面

トレイメニューの「設定」から開けます。

- **ホットキー**: 既定は `Ctrl+Alt+W`。「キーを入力して登録」を押してから
  登録したい組み合わせをそのまま押すだけで記録されます(修飾キー
  Ctrl/Alt/Shift/Win と、英数字・ファンクションキー・矢印キーなどを自由に
  組み合わせ可能。ファンクションキーのみ単独登録可)。他アプリと衝突する
  場合は自動的に元のホットキーへロールバックされ、その旨を表示します
- **押しっぱなし切替のキー**: 「次のセット」「前のセット」のキーも設定画面で
  変更できます(既定は `↓` / `↑`)。ホットキーの修飾キーを押したままこのキーを
  叩くとセットを送り、修飾キーを離すと確定します(Enter不要・Alt+Tab方式)
- **Codex連携**: 下記参照
- **起動設定**: Windows起動時にRepoDeckを自動起動するかを切り替え
- **モニター自動再接続**: スリープ復帰時に保存済みモニターが認識されていない場合、
  ソフト的にディスプレイを再検出します(既定ON)。トレイメニューの「モニターを再検出」
  からいつでも手動実行できます。管理者権限は要求せず、失敗時は元の表示構成を維持します
- **バージョン情報**: バージョン表示とサードパーティ表示(ライセンス一覧)

### AIエージェント連携(Claude Code / Codex)

RepoDeck はエージェントを起動したり接続したりしません。エージェントが持つ
**ライフサイクルフックの通知先**として同梱の `repodeck-hook.exe` を登録すると、
各ワークセットのリポジトリでの実行状況が、クイックスイッチャーの状態ピルと
トレイアイコンの色に反映されます。

| 状態 | 表示 | 発火するフック |
|---|---|---|
| 実行中 | 青ピル「実行中」 | `UserPromptSubmit` / `PostToolUse` |
| 入力待ち | 琥珀ピル「入力待ち」 | Claude Code: `Notification`、`PreToolUse`(選択プロンプト) |
| 完了 | 「成功」 | `Stop` |

![エージェントバッジの例](docs/screenshots/quick-switcher-agent-badge.png)

イベントは cwd で照合されます。ワークセットのリポジトリ(またはそのサブディレクトリ)
で動いているエージェントが、そのセットの状態として表示されます。`.code-workspace`
で登録したセットは、ワークスペースが指すフォルダーで照合します。

#### Claude Code

1. 設定画面の「hook実行ファイルを確認」で `repodeck-hook.exe` の場所を確認
2. 「Claude Code用settings.json断片をコピー」を押す
3. `~/.claude/settings.json` の `hooks` へ貼り付け(既存のフックがあれば、
   同じイベントの配列に**追記**してください。上書きすると既存のフックが消えます)
4. **新しいセッションから**有効になります(起動済みのセッションは設定を読み込み済み)

登録されるフックは `UserPromptSubmit` / `Notification` / `PostToolUse` / `Stop` と、
`PreToolUse`(`AskUserQuestion|ExitPlanMode` に限定)です。最後の1つは
**選択プロンプトの待ち**を検知するためのもので、Claude Code は選択プロンプトに
`Notification` を出さないため、これが無いと「実行中」のままになります。matcher で
対話ツールに絞っているので、通常のツール実行では発火しません。

#### Codex

「Codex用hooks.json断片をコピー」で、Codex 形式(`commandWindows` キー、入力待ちは
`PermissionRequest`)の断片が得られます。Codex 側の `hooks.json` に貼り付け、Codex の
`/hooks` でフックを信頼してください。

**注意**: フックの登録方法は Codex のバージョンによって異なります(プラグイン形式を
取るものもあります)。お使いの Codex がライフサイクルフックに対応していない場合、
状態は表示されません。

#### 疎通確認

設定画面の「テストイベントを送信」で、実際のフック経路(パイプ→照合→UI)を通した
確認ができます(登録済みのセットが1つ以上必要)。

### 全ウィンドウ回収 / 復旧

- トレイメニューの「全管理ウィンドウを回収」: 登録済みの全ウィンドウをメイン画面へ
  強制的に集約する緊急操作です
- 切替の途中で RepoDeck が異常終了した場合、次回起動時に「前回の切替が中断されました」
  というダイアログが表示され、元の配置に戻す/全ウィンドウをメイン画面へ回収/何もしない
  のいずれかを選べます
- モニター構成が変わった(切断など)結果、画面外になってしまったウィンドウは自動的に
  最小化されます

## 開発

```powershell
cargo test            # 単体テスト
cargo clippy --all-targets --all-features -- -D warnings
.\scripts\build.ps1   # リリースビルド + スタートメニューのショートカット更新
```

- 構成: `src/domain`(純粋なモデル) / `src/application`(ロジック、Win32非依存で
  テスト可能) / `src/windowing`(Win32) / `ui`(Slint)
- `repodeck-hook.exe` はエージェントのフックが叩く小さな中継。stdin の JSON を
  正規化して名前付きパイプへ1回だけ送り、常に終了コード0で抜けます(エージェントの
  セッションを絶対に止めないため)
- 実機での配置検証には `scripts/soak/` の一式があります(テスト制御パイプを有効に
  した RepoDeck を実際に何百回も切り替えて、ズレが無いか確認します)

**注意**: VS Code のターミナルから RepoDeck を起動すると、拡張ホストの環境変数
(`ELECTRON_RUN_AS_NODE` など)を引き継いでしまい、そこから起動される VS Code が
壊れます。`app_launch` 側で該当の環境変数を落としていますが、通常はスタートメニュー
から起動してください。

## 既知の制約

- Windows 専用。仮想デスクトップ機能は使用していません
- 管理者権限で起動されたウィンドウは、RepoDeck が同等以上の権限で動いていない限り
  操作できません(セキュリティ境界のため)
- Windows トースト通知、フック設定ファイルの自動編集、署名付きインストーラー、
  自動更新は未対応
- 同じウィンドウを複数のセットに登録できます。その場合、そのウィンドウは
  アクティブなセットに追従します
